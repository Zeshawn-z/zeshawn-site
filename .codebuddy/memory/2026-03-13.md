## 修复：SpotlightSection 鼠标监听被容器边界限制

### 问题
`SpotlightSection` 使用 `onMouseMove`/`onMouseLeave` 绑定在容器 div 上，鼠标从左右方向移出容器后 `active` 立即变 `false`，卡片边框光效突然消失。

### 解决方案
将监听从容器 div 事件改为 `document` 级别的 `mousemove`/`mouseleave`：
- `document.addEventListener("mousemove", ...)` — 全局监听，不受任何容器边界限制
- 使用 `getBoundingClientRect()` 获取 section 的纵向范围，仅检查 `clientY` 是否在 section 上下各 200px 余量范围内
- 水平方向完全不限制，鼠标在屏幕任意左右位置都能触发卡片光效
- `document.addEventListener("mouseleave", ...)` — 仅在鼠标离开整个浏览器窗口时才设为 inactive
- 移除了旧的 `useCallback` + React `MouseEvent` 导入，改用 `useEffect` + 原生 `globalThis.MouseEvent`

## 站点配置架构优化：消除硬编码

### 问题
`src/lib/site-config.ts` 硬编码了站点名称、社交链接等数据，与"所有数据都在线可改"的目标矛盾。

### 解决方案
- **删除** `src/lib/site-config.ts`（静态硬编码文件）
- **保留** `src/lib/site-config-dynamic.ts` 作为唯一配置源（从 SQLite 读取）
- **新增** `src/components/SiteConfigProvider.tsx`：React Context Provider
  - 接口 `SiteConfigData`：`name`、`social`、`nav`
  - `useSiteConfig()` hook 供客户端组件使用
- **`layout.tsx`**（服务端组件）调用 `getClientSiteConfig()` 从 DB 读取，序列化后传入 `<SiteConfigProvider>`
- **Header、Footer** 改为通过 `useSiteConfig()` 获取数据，不再直接 import 任何配置文件

### 数据流
```
DB(site_config表) → site-config-dynamic.ts → layout.tsx(服务端) → SiteConfigProvider(客户端Context) → Header/Footer
```
